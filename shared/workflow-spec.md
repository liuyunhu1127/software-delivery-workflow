# 工作流执行与状态机规范

## 1. 工作流对象

一个工作流实例包含：工作流编号、项目上下文、启用阶段、当前阶段、阶段会话、成果版本、问题、评审轮次、用户卡点和恢复检查点。上述运行状态统一保存在需求目录根部的`工作流状态.md`，不得拆成多个运行辅助文件。

## 2. 运行目录

运行目录固定为：`<项目根目录>/docs/<需求英文名>/`。

- 需求英文名使用小写连字符形式，例如`login-registration`；
- 只创建当前已经开始的阶段目录；
- 05未启用时不创建05目录或05评审报告；
- 06没有独立阶段目录，最终报告保存在需求级`输出报告/`；
- 实际源代码保存在项目代码目录，03阶段文档只引用代码、Commit、PR/MR和构建证据。

## 3. 阶段状态

| 状态 | 含义 | 允许动作 |
|---|---|---|
| 未开始 | 尚未创建阶段运行 | 启动、跳过 |
| 准备中 | 正在检查输入与适用性 | 补充输入、继续 |
| 执行中 | 正在生成或修改成果 | 保存、暂停、恢复 |
| 待评审 | 成果已达到最小完整条件 | 启动专家评审 |
| 专家评审中 | 正在检查、评分和登记问题 | 保存、异常恢复 |
| 待用户确认 | 已展示分数、意见和风险 | 通过、不通过 |
| 整改中 | 用户不通过，正在处理问题 | 修改、复核、重新评分 |
| 已通过 | 用户确认通过 | 下一阶段、结束 |
| 已跳过 | 阶段不在本次范围 | 记录原因、下一阶段 |
| 已暂停 | 会话或执行资源已释放 | 恢复 |
| 已归档 | 工作流关闭 | 只读查看、复制新工作流 |

任何异常、断线或超时只能将活动状态转换为“已暂停”，不得自动转换为“失败”或删除会话。

## 4. 默认路线

- 完整路线：01 → 02 → 03 → 04 → 05 → 06；
- 05 可跳过：04 → 06；
- 任意阶段可单独启动；
- 单阶段执行不会自动补做前序阶段，但必须登记输入缺口和采用的假设；
- 06 可独立评审指定阶段、指定版本或当前全部成果。

## 5. 阶段启动规则

启动时必须在`工作流状态.md`中维护“适用性”章节：

| 字段 | 说明 |
|---|---|
| 成果项 | 当前阶段标准文档或活动 |
| 适用性 | 必填、条件必填、可选、不适用 |
| 输入来源 | 用户输入、既有文档、代码库、测试平台等 |
| 当前状态 | 缺失、已有、需更新、已确认 |
| 处理方式 | 新建、复用、修订、跳过 |
| 不适用理由 | 仅不适用时填写 |

缺少非关键输入时，可以使用明确标注的假设继续；缺少会改变业务目标、安全边界或生产变更范围的关键输入时，应提出最少量澄清问题。

不得为适用性单独生成文件。

## 6. 专家评审与用户卡点

阶段专家完成以下动作后才能进入用户卡点：

1. 检查全部适用成果及版本；
2. 对每份文档标记符合、存在问题、缺失、不适用、需补充、已整改或已验证；
3. 登记问题并关联到文档章节；
4. 按本阶段评分表统一计算 0—100 分；
5. 给出优点、问题、风险、红线和建议结论；
6. 保存评审证据和评分依据。

进入卡点前必须在评审结论和对用户的消息中列出`待用户确认和评估的问题`：

1. 等待用户确认的关键范围、技术或业务决策；
2. 未关闭问题、风险、专家分歧和红线；
3. 建议延期项、明确的关闭阶段和延期影响；
4. 通过后将锁定的成果/决策以及下一阶段动作。

每项必须有编号、专家建议和用户可作出的决定。没有待确认项时写明“无待确认问题”，不得只展示分数后直接询问通过与否。用户仅回复“通过”时，视为确认所列决策并接受所列延期安排；用户可回复“通过，但……”保留例外。

每阶段只生成一份评审结论，保存在`输出报告/<阶段>-<名称>评审结论.md`。评分直接包含在评审结论中，不生成独立评分表。后续复评更新同一文件并保留轮次历史。

用户回复规则：

- `通过`：锁定当前基线，关闭阶段；
- `不通过`：系统询问或解析问题，进入整改；
- `不通过：<问题说明>`：直接登记用户问题并进入整改；
- 其他表达：在语义明确时映射为通过或不通过，否则只追问一次。

## 7. 整改与复评

整改必须：

1. 在`工作流状态.md`中创建或关联问题编号；
2. 修改全部受影响成果；
3. 增加成果版本；
4. 更新修订记录和追溯关系；
5. 将问题状态更新为“已解决”；
6. 由专家验证后更新为“已验证”；
7. 重新计算阶段分数；
8. 展示上次分数、本次分数和变化原因；
9. 回到相同用户卡点。

整改不得生成独立问题台账、复评报告或检查点文件。

## 8. 工作流状态文件

`工作流状态.md`至少包含：

1. 工作流标识、需求名称和目录；
2. 当前阶段、状态、用户卡点和下一安全动作；
3. 阶段启用及完成情况；
4. 当前会话摘要和已确认决策；
5. 当前阶段成果适用性；
6. 成果版本和位置；
7. 问题、等级、影响文档、状态和验证结果；
8. 阶段评分与复评历史；
9. 最近持久化检查点；
10. 外部动作幂等键和结果。

每次保存覆盖最新状态并在文件内追加必要历史，不为每个检查点创建新文件。

## 9. 并发与幂等

- 同一阶段同一时刻只能有一个可写执行租约；
- 文档保存采用乐观版本校验，避免恢复时覆盖新版本；
- 外部操作必须携带幂等键；
- 部署、数据库变更、发布、通知等动作在恢复前必须先查询执行结果；
- 已成功的不可重复动作不得因会话重放再次执行。
