# 工作流触发协议

## 1. 当前包的可用方式

本目录是可安装的Codex技能源，但仅放在普通工作目录中时，不会自动注册为全局命令。

在当前工作区可直接这样触发：

```text
请读取 F:\codex\software-delivery-workflow\SKILL.md，并为“<项目名称>”启动完整软件工程工作流。
```

技能被安装或放入Codex可发现的技能目录后，可以使用：

```text
$software-delivery-workflow 为“<项目名称>”启动完整流程
```

`$software-delivery-workflow` 是对话中的技能调用方式，不是PowerShell或操作系统命令。

## 2. 支持的触发意图

### 启动完整流程

```text
$software-delivery-workflow 为“会员中心改版”启动完整流程，05上线阶段需要执行。
```

默认路线为01 → 02 → 03 → 04 → 06；只有用户明确启用或项目上下文已确认时才执行05。

### 启动单个阶段

```text
$software-delivery-workflow 为“订单服务”单独执行02设计阶段，已有需求文档在 <路径>。
```

也支持自然语言：

```text
启动软件工程工作流的04测试阶段，只执行这个阶段。
```

### 补充已有阶段

```text
$software-delivery-workflow 补充 WORKFLOW-20260905-001 的02设计阶段，只处理缺失和未关闭问题。
```

### 恢复工作流

```text
$software-delivery-workflow 继续 WORKFLOW-20260905-001
```

或：

```text
恢复上次的软件工程工作流，从最近检查点继续。
```

当存在多个可恢复实例时，系统只列出候选工作流编号、项目、当前阶段和更新时间，请用户选择，不得猜测。

### 查看状态

```text
$software-delivery-workflow 查看 WORKFLOW-20260905-001 的状态
```

状态响应必须包含：当前阶段、阶段状态、已生成成果、最近阶段评分、未关闭问题、等待对象和下一安全动作。

### 单独触发阶段专家评审

```text
$software-delivery-workflow 对 WORKFLOW-20260905-001 的03开发阶段重新进行专家评审
```

### 触发总体专家评审

```text
$software-delivery-workflow 对 WORKFLOW-20260905-001 执行06总体专家评审
```

## 3. 触发参数

| 参数 | 必填条件 | 示例 | 缺失时处理 |
|---|---|---|---|
| 项目名称或工作流编号 | 新建需要项目；恢复需要编号或唯一候选 | `订单服务` | 询问或选择唯一候选 |
| 动作 | 必填 | 完整/单阶段/补充/继续/状态/评审 | 根据明确语义识别 |
| 阶段 | 单阶段、补充、阶段评审时必填 | `02` | 询问阶段 |
| 输入来源 | 有既有成果时需要 | 仓库或文档路径 | 新建时允许为空 |
| 05是否启用 | 完整流程在进入05前需要 | 是/否 | 默认跳过并在04后确认 |
| 需求英文目录名 | 新建需要 | `login-registration` | 从需求名称生成小写连字符形式并展示确认 |
| 输出目录 | 可选 | `<项目>/docs/login-registration` | 使用当前项目下`docs/<需求英文名>` |

## 4. 触发后的初始化

新建工作流时，系统执行：

1. 生成工作流编号：`WORKFLOW-<YYYYMMDD>-<序号或短ID>`；
2. 创建需求目录：默认 `<当前项目>/docs/<需求英文名>/`；
3. 创建当前阶段目录和需求级共享目录`输出报告/`，不预建未来阶段；
4. 在需求目录根部创建唯一的`工作流状态.md`，其中保存会话、适用性、问题、评分历史和恢复检查点；
5. 记录执行模式、启用阶段和05阶段策略；
6. 加载已有输入，将适用性判断写入工作流状态；
7. 展示初始化结果后开始当前阶段。

初始化响应示例：

```text
工作流已启动
工作流编号：WORKFLOW-20260905-001
项目：会员中心改版
模式：完整流程
当前阶段：01需求阶段
05上线阶段：待04完成后确认
需求目录：<当前项目>/docs/<需求英文名>

现在开始检查需求阶段输入和适用文档。
```

初始化及阶段执行不得产生独立的问题台账、适用性清单、检查点、评分表或会话文件。

## 6. 用户卡点触发

专家评分完成后，系统先发送编号化的“待用户确认和评估的问题”，覆盖关键决策、未关闭风险、延期项及通过后的影响；无事项时明确写“无待确认问题”。随后固定发送：

```text
本阶段已完成执行和专家评审。请回复“通过”，或回复“不通过：问题说明”。
```

- `通过`只作用于当前等待确认的阶段，并表示确认已列出的决策及延期安排；
- `通过，但……`允许保留明确例外，例外必须写入状态和基线；
- `不通过：问题说明`创建用户问题并进入整改；
- 单独发送`不通过`时，系统只追问需要调整的问题；
- 当前没有待确认阶段时，单独发送`通过`或`不通过`不得改变工作流状态。

## 7. 防止误触发

以下请求不会自动触发本工作流：

- 普通的一次性代码修改；
- 单纯解释一个技术问题；
- 只要求撰写一份文档但未提及本工作流；
- 普通代码评审但未要求进入03阶段；
- 与当前工作流无关的“通过”或“不通过”。
