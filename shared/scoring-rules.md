# 专家评分与复评规则

## 1. 评分范围

- 文档只做质量检查，不单独评分；
- 01—05 阶段各生成一个阶段分数，范围为 0—100；
- 06 阶段生成一个总体分数，范围为 0—100；
- 05 未启用时不扣分；不适用项不进入分母，但必须记录理由。

## 2. 单项量尺

| 等级 | 判定 |
|---:|---|
| 0 | 完全缺失，无法评审 |
| 1 | 严重不足，存在根本性问题 |
| 2 | 部分具备，但尚不可直接执行或验证 |
| 3 | 基本符合，能够执行，仍有改进空间 |
| 4 | 完整、清晰、可执行并有充分证据 |
| 5 | 优秀，风险控制和追溯证据充分 |

计算公式：

`阶段分数 = Σ（维度等级 ÷ 5 × 维度权重）`

最终结果四舍五入到整数。每个维度必须附评分依据，禁止只给分数。

## 3. 建议区间

| 分数 | 专家建议 |
|---:|---|
| 90—100 | 推荐通过 |
| 80—89 | 推荐通过，可处理少量改进项 |
| 70—79 | 建议调整后通过 |
| 0—69 | 建议不通过 |

## 4. 问题等级

| 等级 | 定义 |
|---|---|
| 严重 | 可能导致重大业务、安全、数据或生产事故 |
| 重要 | 明显影响正确性、可交付性或维护成本 |
| 一般 | 不阻断主要目标，但应在当前或后续迭代修正 |
| 建议 | 最佳实践或体验改进 |

红线风险独立于分数展示，不得被高分抵消。典型红线包括重大安全漏洞、不可恢复的数据变更、核心需求未验证、无法回滚的高风险发布及明确的合规风险。

## 5. 多专家合并

- 每个评分维度指定主评专家；
- 其他专家提供协评分和意见；
- 主评与协评相差 2 个等级及以上时，标记“专家分歧”；
- 分歧必须展示各自依据，不得静默平均；
- 无分歧时按该维度所有有效专家评分的算术平均值计算。

## 6. 复评

复评必须保留：评审轮次、上次分数、本次分数、变化值、已解决问题、未解决问题、新增问题、成果版本变化和专家意见变化。

用户通过时，保存当轮分数作为阶段基线。用户在红线未关闭或专家建议不通过时仍决定通过，必须登记风险接受人、理由、范围和复查日期。
