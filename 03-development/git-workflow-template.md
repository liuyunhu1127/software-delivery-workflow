## 3. Commit规范

- 每个提交只表达一个逻辑变更；
- 提交信息包含类型、范围、摘要和关联工作项；
- 禁止提交密钥、构建输出和无关格式化；
- 可回滚性差的变更必须单独提交。

示例：`feat(review): add stage scoring [REQ-123]`

## 4. Pull/Merge Request

PR/MR必须包含：目的、范围、关联需求与设计、风险、验证证据、数据或配置变化、回滚方法和截图/演示（适用时）。
